# 自定义路由管理工具

`gost-route-manager` 是一个小型桌面前端：简单场景可用 Gust 的 `tungo` 将指定网段转发到 SOCKS 或自定义 `-F` 链，复杂场景可直接填写整组 gost 参数。界面和托盘由 Go/Fyne 实现，不需要安装 Qt 运行库。

## 功能

- Windows、macOS 和 Linux 桌面；支持直接以管理员/root 身份运行。
- 普通用户可以查看和编辑配置。点击“提权”或尝试运行隧道时，会调用 Windows UAC、macOS 管理员授权或 Linux polkit。
- 记录支持新增、编辑保存、删除、运行和停止；关闭窗口后仍驻留托盘。
- “路由管理”模式自动生成 TUN 监听和路由：目标可直接填写 SOCKS 地址，也可填写一个或多个完整的 `-F` 组成穿透链。
- “自由参数”模式只固定记录名字，其余内容全部作为 gost 参数传入，例如 `-L ... -L ... -F ... -F ...`；不需要也不能在前面输入 `gost`。
- 同一配置只允许一个管理器实例；重复启动会恢复并聚焦已运行实例，不会再创建窗口。普通窗口提权时会把实例锁安全交接给高权限窗口。
- 左键点击（包括双击）托盘图标可恢复主界面；右键仍显示托盘菜单。
- 新增记录保持空白，输入框中的示例是 placeholder，不需要先手工删除。
- 已点击“运行”的隧道会被持续守护：进程退出后按 1、2、4、8、16 秒退避重启，并由 10 秒巡检兜底；点击“停止”会同时取消守护和待执行的重启。端口占用会立即停止守护，其他快速启动失败连续 5 次后自动熔断，修正配置后可手动重新运行。
- 日志使用有界 ring buffer：每个隧道保留最近 100 行，“全部日志”保留所有隧道最近 1000 行；单行最多 4096 个字符。日志窗口每秒检查版本并自动刷新，无变化时不会复制或重新格式化日志，关闭窗口即停止刷新任务。打开和刷新时自动定位到最新一行；任务日志与全部日志均可确认后手动清空，清空只影响内存日志，不停止隧道或删除配置。
- 隧道退出提示只展示最新一条有效错误并限制长度，不会把整个日志缓存塞入提示框；完整历史从任务日志页面查看。
- QtUI 发行包将专用后端命名为 `gost-qt`。启动时会扫描没有活动管理器父进程的遗留 `gost-qt`，在顶部显示“孤儿服务”数量；高权限状态下点击即可确认清理。当前管理器持有的任务和普通 `gost` 进程不会进入清理范围。
- 手动运行会先把实际 `gost-qt` 可执行文件和完整参数写入任务日志，然后直接启动，不再额外确认。孤儿清理仍需确认，并逐项显示 PID、启动时间、可执行文件、原启动命令及实际清理动作。
- 配置优先持久化为程序同目录的 `route-manager.json`，适合解压即用和整体迁移；首次升级会把已有用户配置复制过去。程序目录不可写时回退到用户配置目录下的 `gust/route-manager.json`。提权时始终沿用同一个配置文件。
- 每条“路由管理”记录使用独立、稳定的 TUN 地址和接口名，可同时运行多条记录。
- 运行、停止、守护重启和错误状态只刷新对应记录的状态徽标与按钮；新增、删除或切换模式时才重建列表，记录较多时不会因单条状态变化重绘整个页面。

## 输入格式

路由条目使用逗号分隔，至少包含一个 CIDR；还可以追加 DNS 和 MTU：

```text
192.0.2.0/24,198.51.100.0/24,203.0.113.0/26,dns=192.0.2.53,198.51.100.53,mtu=1420
```

目标只写地址时默认使用 SOCKS5：

```text
192.0.2.37:5555
```

也可以填写完整的 Gust `-F` URL；单个目标的 `-F` 可省略，多级穿透链则依次填写多个 `-F`：

```text
socks5://user:password@192.0.2.37:5555
-F http2://proxy.example.com:443
-F socks5://192.0.2.37:5555 -F relay+wss://proxy.example.com:443
```

“自由参数”模式不会自动添加任何监听、转发或路由参数，整行直接交给 gost：

```text
-L tcp://:8080 -L udp://:5353 -F socks5://192.0.2.37:5555 -F relay+wss://proxy.example.com:443
```

## 构建和运行

构建当前平台的管理器时会同时生成专用的 `gost-qt` 后端；两个程序放在同一目录即可自动发现：

```sh
make route-manager
bin/gost-route-manager
```

也可以显式指定路径：

```sh
bin/gost-route-manager --gost /path/to/gost-qt
```

Windows 原生终端中使用 `make route-manager-windows`（需要可用的 C 编译器和 Fyne/GLFW 开发环境）。最终二进制使用 `-s -w` 去除调试信息，且不携带 Qt、Electron 或浏览器运行时。

Linux 的 UI 提权依赖 `pkexec`。如果系统没有 polkit，可以直接执行 `sudo bin/gost-route-manager`；传入 `--config` 可以继续使用普通用户的配置文件。

## 安全边界

普通权限状态不会启动任何隧道。只有高权限实例会创建 TUN 设备、修改路由/DNS 并启动 `gost-qt` 子进程。

管理器不会查找或终止名为 `gost` 的进程，因此不会影响用户在终端、服务管理器或其他程序中启动的普通实例。每条隧道只管理自己创建并持有句柄的 `gost-qt` 进程树：Linux/macOS 使用独立进程组，Windows 使用带 `KILL_ON_JOB_CLOSE` 的 Job Object。停止时先请求进程组正常退出，超时才强制回收该任务的完整进程树；多条隧道会并行清理。若托盘退出无法确认清理成功，主程序会保持运行并提示错误，避免静默遗留后台服务。

孤儿扫描只匹配精确名称 `gost-qt`（Windows 为 `gost-qt.exe`），并在清理前复核 PID、启动时间和进程名，避免 PID 复用造成误杀；仍有活动路由管理器父进程的后端及当前实例持有的 PID 会被排除。
